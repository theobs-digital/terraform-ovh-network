# Changelog

All notable changes to this module are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this module adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **BREAKING**: variables aligned on the provider's attributes:

  | Before | After |
  |---|---|
  | `network_name` | `name` |
  | `network_region` | `regions` |
  | `network_vlan_id` | `vlan_id` |
  | `subnets.cidr` | `subnets.network` |
  | `subnets.start_ip` | `subnets.start` |
  | `subnets.end_ip` | `subnets.end` |
  | `subnets.dhcp_enabled` | `subnets.dhcp` |
  | `subnets`, a list | `subnets`, a map: key each subnet by its `region` to keep it in the state |
  | `gateways`, a list | `gateways`, a map: key each gateway by its `region` to keep it in the state |

- **BREAKING**: `regions` left out puts the network in every region, the provider's default, instead of `EU-WEST-PAR` alone. To keep a network created without `regions` as it is, set `regions = ["EU-WEST-PAR"]`; otherwise the next apply extends it to every region, in place. `regions = []` is no longer refused, and means the same. The output `network.regions` gives the regions the provider reads, a set
- `vlan_id` takes 0, a network without VLAN, as the API does, and refuses more than 4095
- **BREAKING**: Terraform 1.4 or later. `terraform_data` carries the preconditions instead of `null_resource`, and the module no longer needs the provider `hashicorp/null`. The first plan replaces `null_resource.validations` with `terraform_data.validations`, two entries of the state with nothing behind them at OVHcloud

## [0.1.0] - 2026-10-17

### Fixed

- Terraform 1.3 to 1.11: a call without `network_name` or `network_region` failed, because `&&` and `||` evaluated `length()` on `null` too; Terraform evaluates only one side since 1.12
- `subnets` defaults to `[]`, as the README said: a network without subnets needed `subnets = []`
- `gateways`: `name` and `model` are required, as the provider requires them; leaving one out failed on `length()` of `null` instead of the validation message
- README: `create_subnet` defaults to `true`, not `false`; the gateway example put a gateway in a region the network was not in

### Added

- `versions.tf`: Terraform 1.3 or later, provider `ovh/ovh` `~> 2.5` for the `regions_openstack_ids` attribute of `ovh_cloud_project_network_private`, and `hashicorp/null` `~> 3.0`, which `null_resource` needed but nothing declared
- Tests on `mock_provider`: the network, its subnets and gateways, the preconditions and the validations
- Examples `basic` and `complete`
- `CHANGELOG.md`, `LICENSE` (MIT), `.gitignore`, `.pre-commit-config.yaml`, `.tflint.hcl`, `.terraform-docs.yml`, and the workflow `Checks`: the pre-commit hooks and the mock tests on every pull request and push to `main`, and a validation with Terraform 1.3.10, provider `ovh/ovh` 2.5.0 and `hashicorp/null` 3.0.0, the bottom of the requirements

### Changed

- `provider.tf`, `variable.tf` and `output.tf` renamed `versions.tf`, `variables.tf` and `outputs.tf`
- README: a Requirements table with the releases the module was checked with, the module taken from `github.com/theobs-digital` instead of a local path, and the reference generated by terraform-docs
